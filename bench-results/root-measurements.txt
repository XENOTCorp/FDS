# root-only measurements (sched tracepoints, bpftrace, slabtop) — 2026-08-24
# host: xenot | cpu: i5-5200U | kernel: 7.2.0_1 (custom Void build)

## 1. sched:sched_switch call graph under TCP load (perf record -g)
# 18.07% of context switches originate in __schedule via
#   tcp_sendmsg -> tcp_sendmsg_locked -> sk_page_frag_refill ->
#   skb_page_frag_refill -> alloc_pages -> get_page_from_freelist ->
#   clear_highpages_kasan_tagged
# => the kernel ZEROES every page allocated for skb frags.
# CONFIG_INIT_ON_ALLOC_DEFAULT_ON=y (verified in /proc/config.gz;
# no KASAN). Every datapath page alloc pays a full-page memset.
# Disable with boot param `init_on_alloc=0` (needs reboot; it is a
# security tradeoff — init_on_alloc prevents uninitialized-memory
# leaks). This is a root-level, measurable %sys reduction.
