# MSG_ZEROCOPY verdict (UDP echo, fds engine) — 2026-08-24
# host: xenot | cpu: i5-5200U | kernel: 7.2.0_1 (custom Void build)
# tool: --bench-udp-against (4 sockets x 64 in-flight 60 KiB, 4 s)

## A/B (new --bench-udp-against client)
baseline (sendmmsg copy)    10.38 Gbps sent / 10.37 Gbps echoed / 99.86% completion
FDS_UDP_ZEROCOPY=1           8.18 Gbps sent /  7.86 Gbps echoed / 96.09% completion
                             (engine auto-disabled zerocopy after 5 ms grace:
                              "udp zerocopy sends not completing (kernel copies
                              silently?) — disabling zerocopy for this worker")

## why: this kernel silently copies UDP MSG_ZEROCOPY (verified)
- Mutation probe: send 60 KiB with MSG_ZEROCOPY, mutate the buffer
  BEFORE the peer reads -> peer receives the OLD bytes => the kernel
  copied at send time; the user pages are never referenced.
- Same result with UDP_CORK set (the documented corked path).
- Notifications: 3 ZC sends -> 1 coalesced notification with an EMPTY
  byte range (ee_info == ee_data == 0) — neither byte ranges nor
  notification counts can drive buffer recycling here.
- SO_ZEROCOPY setsockopt succeeds unprivileged (the old "requires
  CAP_NET_RAW" comment was wrong), but the datapath ignores it.

## engine behavior (safe by construction)
- drain_udp_zc: two receive-buffer sets alternate; a set is not reused
  until its in-flight sends are notified (never a use-after-free, even
  on kernels where ZC DOES reference pages).
- 5 ms stall guard: if no notification frees a set within 5 ms, the
  worker logs once, disables zerocopy, and falls back to the copy path
  (drain_udp) — it can never wedge on a kernel that copies silently.
- Feature stays opt-in (cfg.udp.zerocopy / FDS_UDP_ZEROCOPY, default
  off). On kernels/NICs where MSG_ZEROCOPY engages (real NICs, vanilla
  kernels), the same code takes the zero-copy path; on this kernel it
  self-disables and costs ~5 ms of stall at startup.

## verdict
Third measured case (after PGO, io_uring) where a "modern" optimization
loses on this kernel: MSG_ZEROCOPY adds per-datagram sendmsg syscalls
without removing the copy. The kernel datapath is the wall.
